输入只录一次

三段测试

每一段都是为了引出一种已知的失败。主题可以换成你的学科，陷阱留着。第一段故意是英语，因为它测的就是英语技术旁白。

In this lesson we deploy version 2.10 of the API to a Kubernetes cluster. First, run kubectl apply with the manifest file. If the pod stays in CrashLoopBackOff for more than 30 seconds, check the logs. Why does this happen? Usually, the container can't reach PostgreSQL on port 5432. Let's fix that now, step by step, without rushing.

陷阱：版本号、缩写（API）、代码词（kubectl、CrashLoopBackOff）、端口号、一句要升调的问句，以及一句平静的收尾。

今天我们来看银行系统的重新设计。第一步，执行数据迁移，把旧表里的数据转到新表中；第二步，给每个用户重新分配权限。这个功能已经上线了吗？还没有，预计在2026年第四季度完成，大约需要3.5个人月。好，我们一步一步来，不着急。

陷阱：多音字 行（银行 háng / 执行 xíng），重（重新 chóng），给（gěi，不是 jǐ），了（le，不是 liǎo）；年份、季度和小数；问句；放松的结尾。

接下来我们用 Docker Compose 启动三个服务：一个 Redis 缓存，一个 FastAPI 后端，还有一个 React 前端。注意，environment variables 要写在 .env 文件里，不要直接提交到 GitHub。If you work mainly in English, the same rule applies: never commit secrets.

陷阱：普通话里的英语产品名，句中切换语言，一个文件名（.env），以及最后一句英语：声音跨语言时身份还在不在？

每个工具把每一段生成三次（能换种子就换），第 1 段用英语参考，第 2 段用普通话参考，第 3 段两种参考各做一遍。这样能把运气和能力分开，也能看见参考语言怎样影响口音。推断

第二部分：给编程智能体的提示

把下面这段贴进编程智能体（Cursor、Claude Code、Codex 或同类），放在一个空文件夹里。它会按第 8 页，围绕你对比里赢的那个语音合成来搭流水线。先改方括号里的部分。提示用中文写，文件名和接口名保持英文，方便代码对得上。

你在搭建一条双语（英语 / 普通话）技术课程的旁白流水线，用我自己的克隆声音。在这个文件夹里工作。Windows 11，Python 3.11+，ffmpeg 在 PATH 上。

语音引擎：[ElevenLabs eleven_v4，voice_id 来自环境变量 ELEVEN_VOICE_ID | 本地模型 X，走它的 Python API]
引擎后面只留一个接口：synthesize(text, lang, seed, context) -> wav_path, request_id。
密钥只从环境变量读。绝不把密钥或我的声音录音写进 git。

输入
- lessons/<id>/script.md ：显示文本，带幻灯片标记 "<!-- slide N -->" 和语言标签 [en]/[zh]。
- lexicon.yaml ：术语 -> {en: 别名或国际音标, zh: 拼音覆盖}，外加一份「受保护术语」清单。
- settings.yaml ：钉死的 model_id、voice_id、声音设置、词典版本、参考片段路径和 sha256、
  种子策略、采样率 48000 单声道、响度目标 -16 LUFS / -1.5 dBTP。绝不用 "latest"。

阶段（每个阶段一个命令行子命令；每阶段可重入、可续跑）
1. normalize ：显示文本 -> 口播文本。展开数字、版本、单位、日期、缩写；把代码改写成能念的话。
   中文用 WeTextProcessing。应用 lexicon.yaml。显示文本和口播文本并排保留。
2. chunk     ：每块 1–3 句，绝不跨过幻灯片标记。写出 chunks.jsonl
   （幻灯片、语言、口播、显示、预期时长）。
3. synth     ：缓存键 = sha256(口播 + model_id + voice_id + 设置 + 词典版本 + 种子 + 参考哈希)。
   已有则跳过。ElevenLabs 传入前后请求编号（最多 3 个，不到 2 小时）以保持连贯，并把
   request-id 和 character-cost 响应头写入 manifest.sqlite。
4. check     ：每一块：时长比 0.7–1.4，削波，两端静音；英语用 faster-whisper large-v3，
   中文用 SenseVoice/Paraformer；规范化后英语词错率 <= 5%，中文字错率 <= 3%；受保护术语都在；
   与参考的说话人相似度 >= 基线 - 0.10（同一个嵌入模型，基线来自 refs/baseline/*.wav）；
   用 UTMOSv2 分数做分诊。写出 qc.csv。
5. fix       ：失败的块换新种子，最多 3 次；仍然失败则标成 "needs_human" 并写原因。
6. assemble  ：修剪两端静音，停顿 300 毫秒（句）/ 800 毫秒（段）/ 1500 毫秒（换幻灯片），
   切口 5–10 毫秒淡化；ffmpeg loudnorm 两遍打到目标；用 pyloudnorm 复核。
7. align     ：把口播稿强制对齐到 lesson.wav（ctc-forced-aligner，或 ElevenLabs 强制对齐 API）；
   words.json 里每个词有起止。
8. captions  ：用显示文本加口播时间做出 SRT 和 WebVTT；中文每行 <= 16 字，英语 <= 42 字符，最多 2 行。
9. video     ：PNG 幻灯片（来自 [Marp | 导出的 PowerPoint]）+ 每张幻灯片由音频得出的时长 -> 用 ffmpeg
   或 MoviePy 做成 MP4。视频以 settings.yaml 里的 "disclosure_text" 开头（口播并且上屏）。
   默认中文声明：本课程旁白使用人工智能合成的本人声音。
10. review   ：生成 review.html，列出每一个 needs_human 的块，再加随机 10% 抽样，带播放器、
   稿子、质检数字，以及按钮：通过 / 重新生成 / 改文本。

交付
- README：确切命令、每课费用估计、质检摘要（按失败类型计数）。
- normalize、chunk、缓存键和字幕换行的单元测试。
- 在 lessons/demo 上跑完整条流水线：每种语言 3 张短幻灯片，并把 qc.csv 给我看。

先问我再做：API 费用超过 [5 美元]、删除任何已生成的音频、或修改 settings.yaml。
