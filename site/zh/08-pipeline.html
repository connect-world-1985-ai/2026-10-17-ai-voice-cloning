第 8 页 · 把它做好

一条由智能体来跑的旁白流水线

一门课，而不是一段演示，工作就变成一条构建流水线：稿子进去，检查过的音频、字幕和按时间排好的视频出来。编程智能体可以写并跑几乎全部。这一页讲阶段、每个阶段的工具和设置，以及你仍然必须听的地方。

结论
  • 把旁白当成编译出来的产物：稿子是源；其余一切由它加上一份钉死的设置文件重新生成。实践
  • 核心循环是规范化 → 切块 → 合成 → 语音识别检查 → 重做失败的 → 组装。每一块按哈希缓存，所以一处修改只碰那一块。实践
  • 按幻灯片生成音频。于是每张幻灯片的时长就是它的音频长度，大部分同步工作消失了。推断
  • 钉死模型编号。ElevenLabs 在 2026-07-09 移除了 v1 模型；用「最新」录的课，以后没法一致地打补丁。已核实（ElevenLabs 更新日志）

整条流水线一眼看完

1. 规范化：从显示稿到口播稿

  • 展开数字、版本、单位、货币和日期；缩写按你怎么说来拼；代码换成能念的转述。两个版本都存；字幕用显示文本。实践
  • 工具：普通话和英语用 WeTextProcessing（Apache-2.0），英语用 NeMo text processing（Apache-2.0）或 num2words（LGPL-2.1），再加一次带明确规则的大语言模型处理。已核实（许可，2026-10-17）
  • 留一份项目词典（仓库里的 YAML）。智能体把它编译成 ElevenLabs 发音词典（有版本）、Azure PLS 词典，或开源模型的行内拼音 / 国际音标。细节在第 7 页。
  • 混合语言的句子（「我们用 kubectl 部署」）在双语教学里是正常的。每个工具都早点测；有的模型会在句中换口音。推断

2. 切块

  • 一块 = 1–3 句（约 100–400 字），绝不跨过 <!-- slide 3 --> 这样的幻灯片标记。实践
  • 把块写进 chunks.jsonl：幻灯片号、语言、口播文本、显示文本。
  • 要遵守的供应商上限：Eleven v4 每次请求 10000 字，v3 是 5000；Gemini TTS 每次请求 8192 个输入词元。已核实

3. 合成

  • 缓存键 = 哈希（口播文本 + 模型编号 + 声音编号 + 设置 + 词典版本 + 种子 + 参考片段哈希）。文件已在就跳过调用。实践
  • ElevenLabs：传 previous_request_ids / next_request_ids（各最多 3 个，不超过 2 小时，v3 上没有）或 previous_text / next_text 来保持连贯。要重做中间一块，传入邻居的请求编号。把响应头 request-id 和 character-cost 存进清单。已核实
  • 开源模型：每一块用同一段黄金参考和同一份文稿；按块生成，不要依赖模型自己的长文本模式。实践
  • 全程生成同一采样率的 WAV（PCM），例如 48 kHz 单声道；最后再编码一次。实践

4. 检查并重做

每一块按这个顺序（先做便宜的）：

  1. 信号检查：时长比在预期的 0.7–1.4，没有削波，首尾静音在限度内。
  2. 语音识别：英语 faster-whisper large-v3，中文 Paraformer-zh / SenseVoice；规范化后英语词错率 ≤ 5%，中文字错率 ≤ 3%；每个受保护术语都在。
  3. 相似度：SIM ≥ 你的基线 − 0.10（和基线同一个嵌入模型）。
  4. 分诊分数：UTMOSv2，用来排你先听哪一块。
  5. 失败时：换种子，最多 3 次；然后改写句子或加词典条目；再标出来给你。

所有门槛都是从基准里的人类基线推出来的建议（第 7 页），不是标准。推断

5. 组装

  • 先剪掉每一块自己的首尾静音（ffmpeg silenceremove 或 pydub detect_leading_silence），再插入受控停顿：句间约 300 毫秒，段间约 800 毫秒，换幻灯片约 1.5 秒。实践（经验法则）
  • 每个切口 5–10 毫秒淡化，避免咔嗒；交叉淡化（10–30 毫秒）只用于连续段落内部。实践
  • pydub（MIT）是做这个最简单的库；ffmpeg 的 concat 解复用器要求格式完全相同。已核实（许可）

7. 词的时间戳（强制对齐）

你已经确切知道说了什么，所以把音频对齐到口播稿，而不是依赖语音识别的时间戳，那些没那么准。实践

工具输出备注（2026-10-17）
ElevenLabs 强制对齐 API字符和词的起止，外加每个词的 loss（置信度）任何音频都能用，包括别的供应商和本地输出。每个词的 loss 同时当发音检查。已核实
带时间戳的 ElevenLabs 语音合成生成音频的字符级对齐v4 在这个端点上是否可用：未核实

8. 字幕

  • 按标点、最大字数和最大时长把词组成一条条字幕；每条结束在最后一个词的结束再加不超过 200 毫秒，绝不和下一条重叠。实践
  • Netflix 风格指南的行限：简体中文每行 16 字（例外 18），最多 2 行，成人最多每秒 9 字；大多数其他语言大约每行 42 个字符。已核实
  • 字幕文字来自显示稿（数字、代码格式），时间来自口播稿的对齐，按词的下标映射。
  • 双语课程：每种语言单独的字幕文件；只有平台不能挂边车 VTT 时才烧进画面。实践

9. 和幻灯片、屏幕录制同步

每张幻灯片一段音频。在稿子里写 <!-- slide 3 --> 或 [[click]] 这样的标记。每张幻灯片的时长 = 它的音频 + 留白。不需要对齐，重做一张只改那一张。幻灯片内部的逐步出现（项目符号），用每个项目第一条的词时间戳。推断

  • 先音频：先生成旁白，再把录屏剪或重定时去配合（ffmpeg setpts 加速，tpad 冻住一帧）。适合你可以便宜重录的教程。
  • 先视频：列出录屏里的事件（点击、场景变化，例如用 PySceneDetect），再把旁白块填进空隙，轻微调速（ElevenLabs speed，IndexTTS 的时长因子）。任何需要超过 ±10% 变速的块，标出来改写。推断
工具同步怎么做许可（2026-10-17）
Remotion（React → MP4）每张幻灯片是一个 <Sequence from={frame}>；帧数 = 秒 × 帧率，来自音频时间。自定义：个人和不超过 3 名雇员的公司免费；超过要公司许可
MoviePy（Python）ImageClip(slide).with_duration(d) + AudioFileClip，再拼接。MIT
只用 ffmpeg每张幻灯片一张 PNG，在 concat 列表里写 duration，再混入音频。LGPL/GPL，看构建
Marp CLIMarkdown → PNG 幻灯片；再用 MoviePy 或 ffmpeg。MIT
reveal.jsHTML 幻灯片；旁白用插件或无头浏览器采集。MIT

一门长课上的一致

  • 在 settings.yaml 里钉死一切：供应商、确切的 model_id（例如 eleven_v4，绝不是 “latest”）、声音编号、声音设置、词典编号和版本、参考片段哈希、种子策略、输出格式、响度目标；开源模型还要 git 提交和检查点哈希。实践
  • 供应商会弃用模型。ElevenLabs 在 2026-07-09 移除了 eleven_monolingual_v1、eleven_multilingual_v1 和 scribe_v1；并且说「我们所有的默认声音将在 2026年12月31日过期」（对你的克隆无关，如果你用库存声音当后备就有关）。已核实（更新日志，帮助中心经研究助手）
  • 留住已发布内容的母带 WAV，旧课就不必重新生成。换模型之后，整课重做，不要单块重做，这样一课里不会混两个模型版本。实践
  • 每隔几个月录一段新的真人样本。你真实的声音也会变，基线相似度告诉你克隆还像不像你。推断
  • 画出一课里每一块的相似度、语速和响度；离群点就是重做的候选。实践

智能体自动化什么，你做什么

智能体

规范化、编译词典、切块、API 调用、缓存、费用跟踪、语音识别 / 时长 / 相似度检查、重试、组装、响度、对齐、字幕、渲染、质检报告。

你

批准新的词典条目；听每一个被标出的块，再加随机 10%；判断重音和语气；把第一节成片从头看到尾；settings.yaml 里任何东西变了就做盲听 A/B。
