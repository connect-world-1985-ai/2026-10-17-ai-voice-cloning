第 7 页 · 把它做好

测量质量，控制输出

「我觉得好听」撑不起四十节课。这一页讲三件你能量的事（像不像我、词对不对、自然不自然），合成语音通常怎么失败，以及每一种失败你有什么控制。

结论
  • 两个自动检查能抓住大多数真问题：用语音识别对着你的稿子算词错率或字错率，以及时长是否合理。每一块都跑。实践
  • 说话人相似度只有相对于你自己的真人对比真人基线才有意义，而且要用同一个嵌入模型。已核实（Seed-TTS 论文；不同模型的刻度不一样）
  • 技术词读错是教学内容里最常烦人的事；在词典里修一次，并单独留一份口播稿。实践
  • 像不像你，重音对不对，还是要耳朵。换工具或换设置时做盲听 A/B（第 11 页）。

三个能测量的问题

1 · 像不像我？

说话人相似度（SIM）：说话人验证模型把每段变成向量；SIM 是两个向量的余弦。只量音色和身份。

2 · 词说对了吗？

可懂度：用语音识别转写生成的音频，再和稿子比。英语用词错率 WER，普通话用字错率 CER。

3 · 自然吗？

自然度 / 偏好：人的评分（MOS、CMOS、A/B），或一个自动 MOS 预测器当便宜的分诊信号。

参照协议：Seed-TTS-eval

几乎每篇近年的零样本语音合成论文都用字节跳动的 Seed-TTS-eval 配方来报数字：英语词错率用 Whisper-large-v3，中文字错率用 Paraformer-zh，相似度用为说话人验证微调过的 WavLM-large。已核实（Seed-TTS 论文，arXiv 2406.02430）

怎么读这张表
  • 同一个人的两段真录音只有大约 0.73–0.75。克隆到 0.70 以上，就是「和你自己换一天一样像」。克隆甚至可以超过真人那一行，因为它把参考片段的麦克风和房间复制得比另一段真录音更紧。已核实（Seed-TTS 论文的解释）
  • 顶尖开源模型在朗读语音上，和人类错误率大约差 1 个百分点以内。中文「难」集（绕口令、重复的词）上，大家仍有 5–9% 的字错率。
  • 这些是参考片段很好的基准句。你的技术词汇会把错误率抬高。推断

  1. 基线只测一次。取 10 对你自己的真录音（不同的句子，同一套设备）。基线 B = 这些对的平均相似度。
  2. 每一块生成的音频都用同一个模型对黄金参考打分。
  3. 相似度 < B − 0.10 就标出来，并画出每课的均值，抓住慢慢的漂移。推断（建议的规则，不是发表过的标准）
相似度告诉不了你的事 相似度会奖励麦克风和房间也对上，不只是声音。它看不见读错、错声调和扁平的表达。一段复制了坏参考里噪声的片段，分数可以很高。短于 2–3 秒的片段分数很吵。实践

实践里的可懂度

工具角色许可（2026-10-17）
Whisper large-v3 / faster-whisper英语语音识别（基准的选择）；faster-whisper 是同一模型跑在 CTranslate2 上，快很多，有词级时间戳。MIT
Paraformer-zh（FunASR）Seed-TTS-eval 用的普通话语音识别。代码 MIT；权重用 FunASR 模型许可（要求署名）
SenseVoice Small中 / 粤 / 英 / 日 / 韩语音识别，带标点和逆文本规范化（use_itn）。MIT（仓库）
jiwer用文本变换流水线算词错率 / 字错率。Apache-2.0

打分前两边都要规范化，否则「3」对「三」、标点和大小写会把错误率灌高：

  • 英语：用 Whisper 自己的 EnglishTextNormalizer，再 jiwer.wer。
  • 普通话：去掉标点和空格，全角转半角，两边用同一种方式映射数字（WeTextProcessing），再逐字算字错率。
建议的每一块门槛 规范化之后，如果英语词错率 > 5%，或中文字错率 > 3%，或任何一个受保护术语（产品名、代码标识符、数字）缺失，或语音识别显示插入了超过 2 个词（幻觉出来的话），就重新生成。推断（我的门槛，大约是上面人类错误率的 2 倍；用你自己的材料来调）

注意。10 个词的句子里错一个词已经是 10% 词错率，所以短块会跳。Whisper 自己会在静音上幻觉，会「纠正」不流利，也会在罕见技术词上失败，造成误报。留一份已知术语白名单，或改用强制对齐的置信度来查（第 8 页）。实践

最便宜的检查：时长

预期时长 ≈ 词数 ÷ 你的语速（英语大约每分钟 150 词，普通话大约每秒 4–5 个字，都是粗数）。真实时长低于预期的 0.7 倍或高于 1.4 倍，几乎总是漏了一句、循环了，或有一段长静音。这不花钱，而且跑在语音识别之前。推断

自然度和偏好

方法听者做什么用来
MOS（ITU-T P.800）每段打 1（差）到 5（优秀）。论文；要很多听者才有意义。
CMOS相对片段 A 给片段 B 打分（例如 −3 … +3）。比较两个系统；Seed-TTS 用 −2 … +2。
SMOS「这和参考声音有多像？」1–5。人感知到的相似度。
MUSHRA（ITU-R BS.1534）几个系统并排打 0–100，有隐藏参照和一个低锚。仔细的多系统测试；webMUSHRA 实现了它。
盲听 A/B随机顺序听两段，没有标签，选更好的。你的主要工具。 20 对以上；二项检验告诉你偏好是不是真的。

标准按一般知识描述；ITU 页面没有取回。实践

自动 MOS 预测器（只做分诊）

  • UTMOSv2（MIT，sarulab-speech）：VoiceMOS 2024 第一赛道（高质量合成语音）16 项指标里 7 项第一，其余第二。默认输出不确定。已核实
  • UTMOS22（MIT）：大多数语音合成论文引用的 “UTMOS” 分数。已核实
  • DNSMOS（微软）：为噪声抑制而做；擅长发现噪声和瑕疵，对韵律弱。实践
  • NISQA-TTS：代码 MIT，但权重是 CC BY-NC-SA 4.0，所以非商用。已核实

这些预测器和听者小组在平均上相关，不是一段一段相关。用它们给要听的块排序，不要用来自动通过或拒绝。实践

失败常见原因能自动抓住吗？主要控制
技术词读错（Kubernetes、nginx、kubectl）词不在训练数据里；字素到音素在猜部分：语音识别里缺了受保护术语；对齐置信度低词典 / 别名 / 国际音标；在口播稿里改拼

数字、版本、日期（“v2.10”、“1.5x”、“3/4”）每个模型规范化方式不同能（对规范化文本算词错率）你自己先规范化。ElevenLabs 文档展示 Flash v2.5 把 “$1,000,000” 读成 “one thousand thousand dollars”。
把代码念出来()、_、-> 这类符号能（输入里的符号就是红旗）绝不发送原始代码；写一个能念的版本

来自评测与流水线的研究笔记，2026-10-17；供应商行为来自供应商文档。供应商专有的行已核实，原因是实践。

控制手段，按供应商和模型

  • Eleven v4 和 v3 没有 SSML <break>。文档：「Eleven v4 和 Eleven v3 不支持 SSML break 标签」。用标点、省略号和音频标签。更老的模型接受 <break time="1.5s"/>，最长 3 秒，但太多会造成不稳定。已核实
  • v4 的行内国际音标：在纯文本里用斜杠写出发音，例如 /ˈkuːbərˈnɛtiːz/。已核实
  • 发音词典：上传 PLS 或 TXT，或用 API 从规则创建（alias 或 phoneme 规则；默认区分大小写）。每次请求最多 3 本词典，每本有版本（version_id）。音素规则只在 eleven_v4、eleven_v3 和 eleven_flash_v2 上工作；其他模型只用别名规则。已核实
  • 方括号音频标签，v3/v4：[whispers]、[excitedly]、[sighs]。v4 跟得更稳，但标签可能被误读成音效请求。专业克隆「没有为 Eleven v3 完全优化」；用 v4。已核实
  • 声音设置：stability 0.5（越高越单调），similarity_boost 0.75，style 0，speed 1.0。已核实（API 参考的默认值）
  • 连贯：previous_text/next_text，或最多 3 个 previous_request_ids/next_request_ids（不超过 2 小时；v3 上没有；编号优先于文本）。seed 是「尽力而为」，不保证。已核实
  • 规范化：apply_text_normalization = auto/on/off；language_code 强制语言。已核实

小冲突：ElevenLabs 有一页说 SSML 音素标签只在 eleven_flash_v2 上工作，一篇博客说英语的 Flash v2 和 Turbo v2。如果你用带词典的 v4，这无关。

  • 最完整的 SSML：<phoneme alphabet="ipa|sapi|ups">、<sub>、<break>、<prosody>、<lexicon uri="…">。已核实
  • 自定义词典 = 放在公开或 SAS 网址上的 W3C PLS 1.0 XML；一个文件一个区域；≤ 100 KB；按 URI 缓存最多 15 分钟；zh-CN 有一套 SAPI 音素。长音频 API 不支持（用批量合成）。已核实
  • WordBoundary 事件给出词、标点和句子偏移（100 纳秒刻度），可以直接做字幕。已核实
  • 经典 Cloud TTS 声音：SSML 带 <phoneme alphabet="ipa|x-sampa">；中文用 alphabet="pinyin"（粤语 jyutping）；每次请求可以有自定义发音。已核实
  • Chirp 3 HD：Google 自己的页面互相矛盾：一页说同步请求的预览里支持 SSML，声音列表说 Chirp 3 HD「不支持 SSML 输入」。依赖之前先测。未核实
  • Gemini TTS 靠自然语言风格提示和行内发声事件来引导，而不是 SSML。已核实
  • IndexTTS2：汉字和带声调数字的拼音混写，例如 打DI1去银行（只接受它拼音词表里的音节）。IndexTTS2.5 增加逐字替换 <行|HANG2> 和英语 CMU 音素 <minute|M IH1 . N AH0 T>；情绪向量（emo_alpha 约 0.6 或更低）和时长因子。已核实（README）
  • Fun-CosyVoice 3：用拼音和 CMU 音素做「发音修补」，例如 对报道[j][ǐ]予好评；标签 [breath]、[laughter]、<strong>…</strong>；自然语言指令控制方言、语速和情绪。已核实（README、example.py）
  • GPT-SoVITS：中文前端用 G2PW 模型消解多音字；没有找到直接的拼音覆盖语法。未核实
  • F5-TTS 和同类流模型需要参考片段的精确文稿；文稿错了，输出会变差。实践
  • pypinyin（MIT）可以帮你生成并检查覆盖清单里的拼音。

文本规范化：口播稿

每份稿子留两个版本：

显示稿
出现在幻灯片和字幕上的：kubectl get pods -n prod，“v2.10”，“¥1,500”。
口播稿
送给语音合成的：“kube control get pods, dash n, prod”，“version two point ten”，“一千五百元”。

智能体用规则加项目词典生成口播稿，新的词典条目和你一起看一次。库：WeTextProcessing（中+英，Apache-2.0），NeMo text processing（Apache-2.0），num2words（LGPL-2.1），或一次带明确规则的大语言模型处理（ElevenLabs 推荐这个）。已核实（许可）

切块、参考片段和种子

  • 在句子或段落边界切，1–3 句（大约 100–400 字）。绝不在句子中间切，也绝不跨过幻灯片标记。实践
  • 每种语言一段黄金参考给零样本模型：5–15 秒，干净，没有音乐或混响，用你平时的麦克风，用你要的讲课语气，结束在完整的一句上，并有精确文稿。每一块传同一段。实践
  • 种子：由块文本和设置的哈希得出，重跑才能复现；要修一块坏的，只改种子。更低的温度或 top-p 更稳，但更平。实践
  • 跨语言：如果你的普通话参考比英语好（或反过来），每种语言两种参考都试。口音从参考带过去的程度，每个模型不同（第 1 页）。推断

什么自动化，什么要耳朵

完全自动化需要人（至少抽一部分）
文本规范化和套用词典自然度和重音的最终判断
对着稿子的词错率/字错率；受保护术语检查「像不像我？」（相似度只是代理）
时长比、静音、削波、峰值检查情绪是否配得上内容
相对基线的相似度；UTMOSv2/DNSMOS 分诊语音识别会「纠正」的细微读错，尤其是普通话声调和多音字
响度规范化和测量节奏和画面上发生的事是否合拍
对齐、字幕、幻灯片计时、渲染每个新词典条目的第一次批准
失败就重生成的循环（最多 3 次，然后标出）听每一个被标出的块，再加随机 10%

分工和 10% 抽样率是建议。推断
