An agent-run narration pipeline

For a course rather than a single clip, the work becomes a build pipeline: script in, checked audio, captions and timed video out. A coding agent can write and run almost all of it. This page describes the stages, the tools and settings for each, and where you still have to listen.

Bottom line
  • Treat narration like a compiled artefact: the script is the source; everything else is regenerated from it plus a pinned settings file. Practice
  • The core loop is normalise → chunk → synthesise → ASR check → regenerate failures → assemble. Each chunk is cached by a hash, so a fix touches only that chunk. Practice
  • Generate audio per slide. Then each slide's duration is simply the length of its audio, and most synchronisation work disappears. Inference
  • Pin model IDs. ElevenLabs removed its v1 models on 2026-07-09; a course recorded on "latest" cannot be patched consistently later. Verified (ElevenLabs changelog)

The whole pipeline at a glance

1. Normalise: from display script to spoken script

  • Expand numbers, versions, units, currencies and dates; spell out acronyms the way you say them; replace code with a spoken paraphrase. Store both versions; captions use the display text. Practice
  • Tools: WeTextProcessing for Mandarin and English (Apache-2.0), NeMo text processing (Apache-2.0) or num2words (LGPL-2.1) for English, plus an LLM pass with explicit rules. Verified (licences, 2026-10-17)
  • Keep a project lexicon (YAML in the repo). The agent compiles it to an ElevenLabs pronunciation dictionary (versioned), an Azure PLS lexicon, or inline pinyin/IPA for open models. Details on page 7.
  • Mixed-language sentences ("我们用 kubectl 部署") are normal in bilingual teaching. Test them early with each tool; some models switch accent mid-sentence. Inference

2. Chunk

  • One chunk = 1–3 sentences (≈100–400 characters), never across a slide marker such as <!-- slide 3 -->. Practice
  • Write chunks to chunks.jsonl with slide number, language, spoken text and display text.
  • Vendor limits to respect: Eleven v4 10,000 characters per request, v3 5,000; Gemini TTS 8,192 input tokens per request. Verified

3. Synthesise

  • Cache key = hash(spoken text + model ID + voice ID + settings + lexicon version + seed + reference-clip hash). If the file exists, skip the call. Practice
  • ElevenLabs: pass previous_request_ids / next_request_ids (up to 3 each, ≤ 2 hours old, not on v3) or previous_text / next_text for continuity. To regenerate a middle chunk, pass its neighbours' request IDs. Store the request-id and character-cost response headers in the manifest. Verified
  • Open models: same golden reference clip and transcript for every chunk; generate per chunk rather than relying on a model's own long-text mode. Practice
  • Generate WAV (PCM) at one sample rate throughout, e.g. 48 kHz mono; encode once at the end. Practice

4. Check and regenerate

Per chunk, in this order (cheapest first):

  1. Signal checks: duration ratio 0.7–1.4 of expected, no clipping, leading/trailing silence within limits.
  2. ASR check: faster-whisper large-v3 (EN) or Paraformer-zh / SenseVoice (ZH); WER ≤ 5 % EN, CER ≤ 3 % ZH after normalisation; every protected term present.
  3. Similarity: SIM ≥ your baseline − 0.10 (same embedding model as the baseline).
  4. Triage score: UTMOSv2 to sort what you listen to first.
  5. On failure: new seed, up to 3 times; then rewrite the sentence or add a lexicon entry; then flag for you.

All thresholds are suggestions derived from benchmark human baselines (page 7), not standards. Inference

5. Assemble

  • Trim each chunk's own leading and trailing silence first (ffmpeg silenceremove or pydub detect_leading_silence), then insert controlled pauses: ≈300 ms between sentences, ≈800 ms between paragraphs, ≈1.5 s at slide changes. Practice (rules of thumb)
  • 5–10 ms fades at every cut to avoid clicks; crossfade (10–30 ms) only inside a continuous paragraph. Practice
  • pydub (MIT) is the simplest library for this; the ffmpeg concat demuxer requires identical formats. Verified (licence)

8. Captions

  • Group words into cues by punctuation, maximum characters and maximum duration; end each cue at the last word's end plus ≤ 200 ms, never overlapping the next. Practice
  • Line limits from Netflix's style guides: Simplified Chinese 16 characters per line (18 in exceptions), 2 lines maximum, up to 9 characters per second for adults; most other languages ≈42 characters per line. Verified
  • Caption text comes from the display script (digits, code formatting), timed from the spoken-script alignment, mapped by word index.
  • Bilingual courses: keep separate caption files per language; burn in only when the platform cannot show sidecar VTT. Practice

9. Syncing to slides and screen recordings

Audio per slide. Write markers such as <!-- slide 3 --> or [[click]] into the script. Each slide's duration = its audio + padding. No alignment needed, and regenerating one slide changes only that slide. For in-slide builds (bullets appearing), use the word timestamps of the first word of each bullet. Inference

  • Audio first: generate narration, then cut or retime the recording to fit (ffmpeg setpts to speed up, tpad to freeze a frame). Best for tutorials you can re-record cheaply.
  • Video first: list the events in the recording (clicks, scene changes, e.g. via PySceneDetect), then fit narration chunks into the gaps, adjusting speed slightly (ElevenLabs speed, IndexTTS duration factor). Flag any chunk needing more than ±10 % speed change for a rewrite. Inference

Consistency over a long course

  • Pin everything in settings.yaml: vendor, exact model_id (e.g. eleven_v4, never "latest"), voice ID, voice settings, dictionary ID and version, reference-clip hash, seed policy, output format, loudness target; for open models also the git commit and checkpoint hash. Practice
  • Vendors deprecate models. ElevenLabs removed eleven_monolingual_v1, eleven_multilingual_v1 and scribe_v1 on 2026-07-09; and it says "All our Default voices will expire on December 31, 2026" (irrelevant for your clone, relevant if you use a stock voice as a fallback). Verified (changelog, help centre via research helper)
  • Keep the master WAVs of everything published, so old lessons never need regenerating. After a model change, regenerate whole lessons, not single chunks, so one lesson never mixes two model versions. Practice
  • Record a fresh real sample every few months. Your real voice changes too, and the baseline SIM tells you whether the clone still matches you. Inference
  • Plot SIM, speaking rate and loudness per chunk across a lesson; outliers are regeneration candidates. Practice

What the agent automates and what you do

Agent

Normalisation, lexicon compilation, chunking, API calls, caching, cost tracking, ASR/duration/SIM checks, retries, assembly, loudness, alignment, captions, rendering, QA report.

You

Approve new lexicon entries; listen to every flagged chunk plus a random 10 %; judge emphasis and tone; watch the first finished lesson end to end; blind A/B when anything in settings.yaml changes.
