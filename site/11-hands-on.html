Hands-on: a fair comparison, then a pipeline

Two things to do yourself. First, a small, controlled experiment that tells you which tool sounds most like you, in both languages. Second, a ready prompt that asks a coding agent to build the narration pipeline from page 8.

Record the inputs once

  1. Golden reference clips: one 10–15 s English clip and one 10–15 s Mandarin clip, in your teaching voice, with exact transcripts (page 6). Every tool gets the same clip. For ElevenLabs Instant Clone and GPT-SoVITS, also prepare 1–2 minutes and about 5 minutes respectively.
  2. Ground truth: record yourself reading the three test paragraphs below. These are your "real you" samples for the baseline and for the listening test.
  3. Baseline SIM: compute similarity between pairs of your own real recordings (page 7).

The three test paragraphs

Each one is designed to provoke a known failure. Replace the topic with your own subject, but keep the traps.

In this lesson we deploy version 2.10 of the API to a Kubernetes cluster. First, run kubectl apply with the manifest file. If the pod stays in CrashLoopBackOff for more than 30 seconds, check the logs. Why does this happen? Usually, the container can't reach PostgreSQL on port 5432. Let's fix that now, step by step, without rushing.

Traps: version numbers, acronyms (API), code terms (kubectl, CrashLoopBackOff), a port number, a question with rising intonation, and a calm closing sentence.

今天我们来看银行系统的重新设计。第一步，执行数据迁移，把旧表里的数据转到新表中；第二步，给每个用户重新分配权限。这个功能已经上线了吗？还没有，预计在2026年第四季度完成，大约需要3.5个人月。好，我们一步一步来，不着急。

Traps: polyphones 行 (银行 háng / 执行 xíng), 重 (重新 chóng), 给 (gěi, not jǐ), 了 (le, not liǎo); a year, a quarter and a decimal; a question; a relaxed ending.

接下来我们用 Docker Compose 启动三个服务：一个 Redis 缓存，一个 FastAPI 后端，还有一个 React 前端。注意，environment variables 要写在 .env 文件里，不要直接提交到 GitHub。If you work mainly in English, the same rule applies: never commit secrets.

Traps: English product names inside Mandarin, a code-switch mid-sentence, a file name (.env), and a final English sentence: does the voice keep the same identity across languages?

For each tool, generate every paragraph three times (different seeds where possible), using the English reference for paragraph 1, the Mandarin reference for paragraph 2, and both references in turn for paragraph 3. That separates luck from capability and shows how the reference language affects accent. Inference

Part 2: a prompt for a coding agent

Paste this into a coding agent (Cursor, Claude Code, Codex or similar) in an empty folder. It builds the pipeline from page 8 around whichever TTS won your comparison. Edit the bracketed parts first.

You are building a narration pipeline for a bilingual (English / Mandarin Chinese) technical course,
narrated in my own cloned voice. Work in this folder. Windows 11, Python 3.11+, ffmpeg on PATH.

TTS ENGINE: [ElevenLabs eleven_v4 with voice_id from env ELEVEN_VOICE_ID | local model X via its Python API]
Put the engine behind one interface: synthesize(text, lang, seed, context) -> wav_path, request_id.
Read secrets only from environment variables. Never write keys or my voice recordings into git.

INPUT
- lessons/<id>/script.md : display text with slide markers "<!-- slide N -->" and language tags [en]/[zh].
- lexicon.yaml : term -> {en: alias or IPA, zh: pinyin override}, plus a "protected terms" list.
- settings.yaml : pinned model_id, voice_id, voice settings, lexicon version, reference clip path + sha256,
  seed policy, sample rate 48000 mono, loudness target -16 LUFS / -1.5 dBTP. Never use "latest".

STAGES (each a CLI subcommand; every stage idempotent and resumable)
1. normalize : display -> spoken text. Expand numbers, versions, units, dates, acronyms; paraphrase code.
   Use WeTextProcessing for zh. Apply lexicon.yaml. Keep display and spoken text side by side.
2. chunk     : 1-3 sentences per chunk, never across a slide marker. Write chunks.jsonl
   (slide, lang, spoken, display, expected_duration).
3. synth     : cache key = sha256(spoken + model_id + voice_id + settings + lexicon version + seed + ref hash).
   Skip existing. For ElevenLabs pass previous/next request ids (max 3, <2 h old) for continuity and store
   request-id and character-cost headers in manifest.sqlite.
4. check     : per chunk: duration ratio 0.7-1.4, clipping, edge silence; ASR with faster-whisper large-v3 (en)
   or SenseVoice/Paraformer (zh); WER <= 5 % (en) / CER <= 3 % (zh) after normalisation; all protected terms
   present; speaker similarity vs reference >= baseline - 0.10 (one fixed embedding model, baseline from
   refs/baseline/*.wav); UTMOSv2 score for triage. Write qc.csv.
5. fix       : failed chunks -> new seed, up to 3 attempts; still failing -> mark "needs_human" with reason.
6. assemble  : trim edge silence, pauses 300 ms (sentence) / 800 ms (paragraph) / 1500 ms (slide change),
   5-10 ms fades at cuts; two-pass ffmpeg loudnorm to the target; verify with pyloudnorm.
7. align     : forced alignment of the spoken script to lesson.wav (ctc-forced-aligner, or the ElevenLabs
   forced-alignment API); words.json with start/end per word.
8. captions  : SRT and WebVTT from display text with spoken timings; zh <= 16 chars/line, en <= 42, max 2 lines.
9. video     : PNG slides (from [Marp | exported PowerPoint]) + per-slide durations from audio -> MP4 via ffmpeg
   or MoviePy. Start the video with the line from settings.yaml "disclosure_text" (spoken and on screen).
10. review   : generate review.html listing every needs_human chunk plus a random 10 % sample, with audio
   players, the script text, the QC numbers and buttons approve / regenerate / edit text.

DELIVERABLES
- README with exact commands, a cost estimate per lesson, and a QA summary (counts per failure type).
- Unit tests for normalize, chunk, cache keys and caption line breaking.
- Run the whole pipeline on lessons/demo with 3 short slides in each language and show me qc.csv.

Ask me before: spending more than [$5] of API credit, deleting any generated audio, or changing settings.yaml.

The thresholds, pauses and loudness values come from pages 7 and 8 and are suggestions, not standards. Inference
